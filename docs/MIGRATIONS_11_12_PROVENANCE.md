## Limits of this verification
- The Production migration history is **not recorded in the database** (there is no `supabase_migrations` ledger; migrations were pasted by hand), so "applied" is inferred from objects and bodies, not from a ledger.
- File 11's exact bytes are not proven by a recorded hash; the bodies and objects match Production, but a comment-only or whitespace-only difference from the originally applied text could not be detected.
- Policies, triggers and column definitions introduced by these files were not compared one by one; the whole-schema fingerprints in the 2026-10-21 backup baseline (and the identical 2026-11-05 audit counts) cover them indirectly.
