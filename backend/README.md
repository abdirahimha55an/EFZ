# EFZ Backend Architecture Preparation Layer

This directory acts as the preparation layer for migrating the EFZ platform from pure `localStorage` to a secure, enterprise-ready Microsoft SQL Server backend.

> [!IMPORTANT]
> **Safety Notice:** The current frontend application remains completely decoupled from this backend layer and continues to run on the synchronous, robust `localStorage` facade. None of the production UI elements will break or connect to SQL Server during this stage.

## Directory Structure

```
backend/
├── README.md                # This architecture documentation
├── config/                  # Server and Database configurations
│   ├── app.config.ts        # App environment variables (PORT, Secret, etc.)
│   └── db.config.ts         # SQL Server connection settings placeholder
├── db/                      # Database connection and ORM/Client layer
│   └── connection.ts        # Tedious/MSSQL client initializer placeholder
├── api/                     # REST API / Next.js API Routes structure

│   ├── products.ts

```

## Migration Connection Strategy (Future Phase)

When we are ready to connect this backend to the live UI:
1. **API Endpoints Integration:** Replace the current client-side `storage` facade calls in `lib/storage.ts` with standard asynchronous `fetch()` requests targeting our `api/` routes.
2. **State Management Migration:** Transition state-loading hooks in React page components to support asynchronous loaders (using React `Suspense`, loading states, or SWR/React-Query).
3. **Authentication Token Flow:** Convert the client session manager to use stateful HTTP-only JWT cookies generated by the backend API user session routes.
4. **Data Sync / Migration script:** Run a script that reads current `localStorage` records, validates them through the newly developed `validators/`, and bulk-inserts them into the MSSQL database using the custom T-SQL stored procedures.
